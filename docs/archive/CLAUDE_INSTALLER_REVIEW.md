Two concrete blockers for a true double-click install on a fresh Mac:

1. **Piped Homebrew installer can hide interactive prompts.** `Meeting OS.command` runs `install-mac.sh 2>&1 | tee installation.log`. Since stdout is piped (not a tty), Homebrew's installer switches to fully-buffered output, so its `Press RETURN to continue or any other key to abort` and sudo password prompts may not appear on screen until the buffer flushes — the terminal will look hung while it's actually waiting on stdin. This is a known gotcha with `cmd | tee` and interactive installers; worth verifying live since it's untested on a clean Mac.

2. **Quarantine/exec-bit loss on transfer.** The flow depends on `Meeting OS.command`, `scripts/install-mac.sh`, `scripts/setup.sh`, `scripts/build-capture.sh`, and `scripts/build-desktop.sh` all being executable and unquarantined. If the repo reaches the other Mac via zip/AirDrop/USB rather than `git clone`, execute bits are often stripped and files get `com.apple.quarantine`, so double-clicking `Meeting OS.command` either opens it in an editor or Gatekeeper blocks it outright — before any of your install logic runs. Confirm the transfer method, or have the installer/README call out `chmod +x` and right-click→Open (or `xattr -dr com.apple.quarantine`) as a prerequisite.
