# Retry-only ASR checkpoints — implemented

`run_retry` wraps only CPP ASR after pipeline construction. Live, ordinary imports and benchmark commands do not use this cache. Complete raw ASR rows are stored in the meeting SQLite database with a cascading meeting FK. Only exact region input and ASR identity can hit; diarization, embeddings, speaker identity, final source/digest checks and atomic transcript replacement still run.

Identity includes full model/executable content hashes, adapter/parser/checkpoint-code hashes, decoder options, prompt/language, relevant environment and platform. Artifact signatures and resolved executable/model targets are checked before lookup/compute and after native compute. Mid-attempt identity changes reject output. Exact contiguous little-endian float32 samples plus16kHz rate define each audio key. Native failures never produce entries.

Atomic rows have payload SHA256, validated text/row/word timing structure, up to2MiB each. Size-gated SQL avoids transferring oversized payloads into Python; corrupt or mismatched payloads are removed and recomputed. Deterministic LRU caps total declared payload64MiB and4096entries; this is not a physical SQLite/WAL file-size guarantee. Empty successful output is reusable. SQLite cache-operation failures fall back to native computation and increment diagnostics. Setup failures still propagate. Cache tables share Store's foreign_keys=ON connection; actual cascade deletion is tested. They do not participate in RetryStore's protected transcript snapshot.

Diagnostics emit only hit/miss/error counts to stderr. No raw audio is stored in cache and no data is uploaded. Raw ASR text is private local data like the meeting database; entries survive aborted retries and are bounded by eviction/cascade deletion. No automatic retry loop and no relaxed resource guards.
